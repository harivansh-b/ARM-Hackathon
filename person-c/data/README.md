# Public SMS Corpus

## Person-C multilingual starter dataset

`sms_multilingual.jsonl` is a small, synthetic, hand-reviewed starter dataset
for the updated demo requirement. It contains English, Hindi and Hinglish
messages, with both scam and legitimate Indian transactional examples.

Each row has this shape:

```json
{
  "id": "ml-001",
  "campaign": "bank-kyc-hi-1",
  "label": 1,
  "language": "hi",
  "category": "kyc_impersonation",
  "source": "synthetic",
  "text": "..."
}
```

`label` is `1` for scam/smishing and `0` for benign. `campaign` groups related
templates and must be kept intact when splitting data. `language` is metadata
for per-language reporting; the classifier still trains on message text.
`source: synthetic` means these examples are safe demo fixtures, not evidence
of real-world prevalence. Replace or supplement them with consented,
anonymised, licensed data before making production claims.

Train the multilingual starter artifact from `person-c` with:

```text
python -m guardian_models.train_sms data/sms_multilingual.jsonl artifacts/sms-multilingual.json --holdout-fraction 0.25 --epochs 12
```

The trainer holds out complete campaigns. This is more honest than randomly
splitting individual messages because near-duplicate scam templates otherwise
leak into the test set.

The starter set is intentionally small enough for a laptop and demo. Its
evaluation numbers are smoke checks only. For the final report, add consented
or licensed messages, at least several independent campaigns per language and
hard negatives such as legitimate OTPs, UPI receipts, bank alerts and delivery
updates. Always report results separately for `en`, `hi` and `hinglish`.

## Playwright-collected public multilingual corpus

Run `node tools/scrape_public_sms.js` from `person-c` to create
`public_sms_multilingual.jsonl`. The scraper currently collects the English and
Hindi columns from the public Hugging Face dataset
`dbarbedillo/SMS_Spam_Multilingual_Collection_Dataset` and writes provenance to
`public_sms_multilingual.sources.json`. The latest collection produced 10,271
records: 1,254 positives and 9,017 negatives.

The dataset card says the Hindi column is machine-translated from the original
English SMS Spam Collection and declares a GPL license. Treat it as useful for
multilingual robustness testing, not as native Hindi ground truth. Review the
license and cite the original SMS Spam Collection before redistribution or
competition submission. The public source does not provide a verified Hinglish
column; Hinglish should remain separately labelled as synthetic or consented
data.

The same scraper keeps the older phishing and SMS Spam Collection outputs in
`public_sms.jsonl` for backwards compatibility. It redacts phone numbers and
email addresses but does not make the messages safe for production use.

`public_sms.jsonl` is generated by `tools/scrape_public_sms.js` through Playwright from two publicly accessible sources. It is retained as a reproducible research input, not as an assertion that the sources have identical collection methods or labels.

The scraper redacts phone numbers and email addresses, deduplicates exact phishing-message text, and assigns a template-derived campaign group. The legacy corpus does not provide true campaign IDs, so its template groups are only a leakage-reduction heuristic.

Before redistribution or competition submission, review the source terms and cite the original papers. Do not report metrics from this corpus as production performance without a time-ordered or campaign-held-out evaluation and hard-negative analysis.
